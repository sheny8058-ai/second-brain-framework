# 撑不住阈值闸口

任何架构改动冲动，必须先过阈值闸口。

## 流程

1. **查表**：在 `治理/阈值登记.md` 找到对应信号
2. **看实测值**：当前值是否越过阈值
3. **判定**：
   - 未触发 → 按住不动，本表就是"为什么不改"的凭据
   - 已触发 → 允许进入重构

## 规则

- 阈值必须可测、必须有当前实测值、必须写判定结论
- 禁止登记"感觉该重构了"这类无信号改动冲动
- 没有信号 = 不许改
- 超过 30 天的实测值在使用前须重测
- 未实现 ≠ 未触发，不得据此声称架构已验证

## 反模式

- **无信号改动**：找不到触发阈值的改动冲动，一律按住
- **凭旧值续期**：标注"未实测"的信号，下次必须先补测
- **未实现当未触发**：对象未落盘时不得评估，冻结为"已立项未开工"

## 阈值表位置
